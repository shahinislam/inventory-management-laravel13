Inventory

An inventory and point-of-sale system for shops, built on the latest Laravel stack: a single-page Livewire app with Flux UI and Tailwind CSS.

  • Laravel 13
  • Livewire 4 · SPA
  • Flux UI 2
  • Tailwind CSS 4
  • Alpine.js
  • Vite 8
  • PHP 8.3
Version 1.0 Author Qaswasoft Support shahin.sec.cse@gmail.com

Introduction

Thank you for purchasing Inventory. This guide takes you from a fresh download to a working shop: installation, configuration, user roles and day-to-day settings.

What's included

  • Point of sale: barcode scanning, held sales, split payments (cash, card, mobile wallet, bank transfer), 80 mm thermal receipts.
  • Stock: multiple warehouses, batches with expiry dates, stock adjustments, transfers, stock counts and barcode label printing.
  • Sales: invoices with due tracking and payments, sales returns, cash shifts with a Z-report, customers with member rewards, and promotions.
  • Purchasing: purchase orders, supplier payments, purchase returns and payment accounts.
  • Finance and reports: expenses, plus reports for stock, sales, low stock, dues, accounts, expiry and profit & loss. Partner investment and profit reports are also included.
  • Marketing: SMS to members through your own HTTP SMS gateway.
  • Administration: four user roles, your own brand colours and logo, and light/dark mode.

Package contents

  • inventory/ is the application (a Laravel project). The pre-built CSS/JS is already in public/build.
  • documentation/ is this guide.

Technology

Inventory uses the current versions of the official Laravel ecosystem. There is no separate JavaScript framework or API to maintain: the whole app is PHP and Blade, yet it behaves like a single-page application.

Livewire 4 · single-page app

Every screen is a Livewire component. Links use wire:navigate, so moving between pages swaps the content without a full browser reload, and notifications carry over from page to page. Forms, searches, filters and the POS cart update in place without page refreshes.

Flux UI 2

The official component library from the creator of Livewire: buttons, inputs, modals, dropdowns, tables and navigation with consistent styling, keyboard support and built-in dark mode.

Tailwind CSS 4

Utility-first styling on the new Tailwind engine. Your three brand colours are expanded into full shade ranges and applied app-wide through CSS variables, with no rebuild needed.

Laravel 13

The latest Laravel on PHP 8.3, with Fortify for sign-in, password resets and login throttling.

Alpine.js

Small client-side touches like toggles and dropdowns, bundled with Livewire. USB and Bluetooth barcode scanners work with no setup on the POS, invoice, product, purchase, return and stock screens.

Vite 8

A fast asset build with self-hosted fonts. The compiled assets are included, so Node.js is optional.

Pest 4

More than 360 automated tests covering sales, stock, tax, roles and reports are included in tests/.

MySQL / MariaDB

Transactional stock and document numbering with row locks, so two tills can't sell the same last item or reuse an invoice number.

Installation

On a web server

  1. Upload the files. Upload the contents of the inventory/ folder to your server, for example to /home/youruser/inventory.
  2. Point your domain to public. In your hosting panel, set the document root of your domain or subdomain to /home/youruser/inventory/public.

    Important: Never expose the project root itself. Only the public folder should be reachable from the web, otherwise your .env file (with database passwords) could be downloaded.

  3. Create a database. Create an empty MySQL/MariaDB database with collation utf8mb4_unicode_ci, plus a database user with full rights on it.
  4. Create the .env file. Copy .env.example to .env and fill in at least APP_URL, APP_TIMEZONE and the DB_* values. See The .env file.
  5. Run the install commands from the project folder: 
    cd /home/youruser/inventory

# Skip this line if your download already contains the vendor folder
composer install --no-dev --optimize-autoloader

php artisan key:generate --force
php artisan migrate --seed --force
php artisan storage:link
php artisan optimize

    migrate --seed creates the tables, the demo user accounts, default settings and sample data (products, customers, sales and so on), so you can explore every screen. To start with an empty shop instead, see Start without sample data.

    --force is needed because .env.example sets APP_ENV=production, and Laravel asks for confirmation before changing a production database.

  6. Set folder permissions. The web server must be able to write to storage/ and bootstrap/cache/: 
    chmod -R 775 storage bootstrap/cache
  7. Log in. Open your APP_URL in the browser and sign in with the admin demo login. Then change all demo passwords.

On your computer (to try it out)

With PHP 8.3 and MySQL/MariaDB installed (for example with XAMPP), unzip the package and run:

cd inventory
copy .env.example .env          # macOS / Linux: cp .env.example .env
# edit .env: DB_DATABASE, DB_USERNAME, DB_PASSWORD
# for local testing you may set APP_ENV=local and APP_DEBUG=true

composer install                # skip if vendor/ is included
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
php artisan serve

Then open http://127.0.0.1:8000.

Start without sample data

When you are ready to go live with real data, run these instead of php artisan migrate --seed --force:

php artisan migrate --force
php artisan db:seed --class=AdminUserSeeder --force
php artisan db:seed --class=SettingsSeeder --force
php artisan db:seed --class=WarehouseSeeder --force

This gives you the three demo accounts, the default settings and two warehouses (rename or edit them under Inventory › Warehouses). There are no products, customers or transactions.

Already installed with sample data? php artisan migrate:fresh --force followed by the three seed commands gives you a clean start, but it deletes all data, including anything you entered. Only do this before you start trading.

Rebuilding assets (optional)

The compiled CSS and JavaScript are already in public/build. You only need to rebuild them if you edit files in resources/css, resources/js or change Tailwind classes in the views:

npm install
npm run build

If a file named public/hot exists on your server, delete it. It tells the app to load assets from a development server, and pages will appear unstyled.

The .env file

The .env file in the project root holds your server-specific configuration. The important keys:

KeyWhat to set
APP_NAMEThe name shown in the browser tab and emails. Your shop name on receipts comes from Company settings.
APP_ENVproduction on a live server, local on your computer.
APP_KEYLeave empty. php artisan key:generate fills it in. Never share or change it after going live.
APP_DEBUGfalse on a live server. Set it to true only briefly while troubleshooting, because it shows sensitive details on error pages.
APP_URLThe full address of your site, including https://, for example https://shop.example.com. Images and links are built from it.
APP_TIMEZONEYour shop's timezone as a PHP timezone name, for example America/New_York, Europe/London, Asia/Dubai or Australia/Sydney. Default: UTC. Invoices, shifts and reports use it.
DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME, DB_PASSWORDYour database connection.
MAIL_*SMTP settings for password-reset emails. See Email.

Set the timezone before you start selling. Times are stored in the configured timezone. If you change APP_TIMEZONE later, existing records keep their original clock times.

After any change to .env on a server, run php artisan optimize so the new values are picked up (the configuration is cached).

Changing the demo logins

Do this before going live. Anyone who knows these well-known logins can sign in to your shop.

  • Your own account: open the user menu (bottom left) → Settings. Change your name and email under Profile, and your password under Security.
  • Other accounts (admin only): go to Settings › Users. You can edit any user's name, email, role and password, deactivate them, or delete them. Delete or re-assign the demo manager and staff accounts you don't need.
  • The last active admin cannot be demoted, deactivated or deleted, so you can't lock yourself out.

Public sign-up is turned off. New people can only get an account from an admin under Settings › Users.

First steps

A suggested order for setting up a new shop:

  1. Change the demo passwords (see above).
  2. Fill in Settings › General: company details, logo, currency, tax and invoice texts.
  3. Check your warehouses under Inventory › Warehouses. One must be the default.
  4. Add your bank, card and mobile wallet accounts under Purchasing › Payment Accounts.
  5. Create users for your team with the right roles.
  6. Add categories, suppliers and products, or receive stock through Purchasing › Purchase Orders.
  7. Open a cash shift (Sales › My Shift), then start selling from the POS Terminal.

SMS gateway

Inventory sends SMS through any HTTP SMS gateway: you copy the API address and parameter names from your provider's documentation. While the SMS switch is off, messages are only recorded in Marketing › SMS Log and nothing is sent.

FieldPurpose
SMS switchTurns real sending on or off.
Gateway URLYour provider's send endpoint, for example https://api.your-sms-provider.com/send.
MethodPOST sends the values as a form body. GET sends them as URL query parameters. Use whichever your provider documents.
API key, Sender IDThe credentials and approved sender name from your provider.
Parameter namesThe names your gateway expects for each value. Defaults: phone number, message message, API key api_key, sender senderid. Change them only if your gateway uses different names.
Send a thank-you SMS after each member saleSends the Sale message automatically after a sale to a customer.
Sale messagePlaceholders: {name} {invoice} {total} {spent} {shop}
Reward messageSent when a member earns a reward. Placeholders: {name} {reward} {invoice} {shop}
Send a test toSends a test message to the number you enter, so you can check the gateway settings.

Example: if your provider documents https://sms.example.com/api?apikey=…&to=…&text=…&from=…, choose GET, enter https://sms.example.com/api as the Gateway URL, and set the parameter names to to, text, apikey and from.

To send a message to many customers at once, use Marketing › SMS to Members. Every message and the gateway's response are listed in the SMS Log.

Email

The app sends email only for password resets. By default (MAIL_MAILER=log) emails are not sent; they are written to storage/logs/laravel.log. To send real email, enter your provider's SMTP details in .env:

MAIL_MAILER=smtp
MAIL_HOST=smtp.your-provider.com
MAIL_PORT=587
MAIL_USERNAME=your-username
MAIL_PASSWORD=your-password
MAIL_FROM_ADDRESS="shop@your-domain.com"
MAIL_FROM_NAME="${APP_NAME}"

Then run php artisan optimize. Without email, an admin can still set a new password for any user under Settings › Users.

Updating

When a new version is released, download it from your CodeCanyon Downloads page and follow these steps:

  1. Back up your database (for example an export from phpMyAdmin or mysqldump), your .env file and the storage/app/public folder (your uploaded logo and product images).
  2. Turn on maintenance mode: php artisan down
  3. Upload the new files over the old ones. Replace everything (including public/build, and vendor if included) except your .env file and the storage folder.
  4. Run the update commands: 
    composer install --no-dev --optimize-autoloader   # skip if vendor/ is included
php artisan migrate --force
php artisan optimize:clear
php artisan optimize
  5. Turn maintenance mode off: php artisan up

Never run migrate:fresh or --seed on a live shop. migrate:fresh deletes all data, and the seeders add demo accounts and sample data.

If you changed any of the app's code, keep a note of your changes, because the update overwrites them.

Troubleshooting

"500 Server Error" right after installing

  • Check that storage/ and bootstrap/cache/ are writable by the web server.
  • Check that APP_KEY in .env is filled in (php artisan key:generate --force).
  • Read the latest error in storage/logs/laravel.log. You can also set APP_DEBUG=true briefly to see the error in the browser, but always set it back to false.

Pages show no styling

Make sure public/build was uploaded, and delete public/hot if it exists.

Logo or product images don't appear

Run php artisan storage:link, and check that APP_URL matches the address in your browser exactly, including https://.

Image upload fails

Neither the PHP GD nor the Imagick extension is enabled. Ask your host to enable one of them. On XAMPP, open php.ini, change ;extension=gd to extension=gd and restart Apache.

Changes to .env have no effect

Run php artisan optimize:clear and then php artisan optimize.

Dates or times are off by some hours

Set APP_TIMEZONE to your local timezone and run php artisan optimize.

"Too many login attempts"

Each account allows five sign-in attempts per minute. Wait a minute and try again.

The POS asks you to open a shift

Sales are recorded in a cash shift. Open one under Sales › My Shift with your opening cash, then return to the POS Terminal.

Password-reset emails don't arrive

Configure SMTP as described in Email, or reset the password as an admin under Settings › Users.
